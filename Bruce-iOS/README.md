# Bruce-iOS ("Brüce")

A native iPhone client for Bruce Studios, built for iOS 26+ with Liquid Glass throughout. It follows the
original app and [`../Bruce-MacOS`](../Bruce-MacOS/README.md) screen by screen.
Back to the [project README](../README.md) · API reference: [`../API.md`](../API.md).

> **Unofficial.** This is not the Bruce Studios app and is not affiliated with or endorsed by Bruce Studios AB.
> "Bruce Studios" is their trademark.

The home-screen name is "Brüce" (set once in `Config/Base.xcconfig` → `APP_DISPLAY_NAME`); Settings says
"Unofficial client". The app icon is an original redraw, not a copy of Bruce's artwork: it is generated by
`scripts/make-icon.swift` (a gradient in colours similar to the original icon with a system-font "Ü"). Because
it evokes the original brand it is trademark-sensitive; see the project README's Notice section.

## Build & run

```sh
open BruceiOS.xcodeproj                # or:
xcodebuild -project BruceiOS.xcodeproj -scheme BruceiOS \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' build
```

- Deployment target iOS 26.0; builds with the iOS 27 SDK (Xcode 27). iPhone only, portrait.
- Bundle ID `net.dauernheim.bruce`, automatic signing. Simulator builds need no team. For a device,
  copy `Config/Local.xcconfig.example` to `Config/Local.xcconfig` (git-ignored) and set your
  `DEVELOPMENT_TEAM`; it can also override `APP_DISPLAY_NAME`, `PRODUCT_BUNDLE_IDENTIFIER` and the versions.
- The project is a hand-written Xcode 16+ project using folder-synchronized groups: every `.swift` file in
  `BruceiOS/` and `../Shared/BruceCore/` is compiled automatically, so adding files needs no project edits.

### Demo mode (hidden developer switch, fully offline)

This is the real app; demo mode exists only for screenshots and tests and is never reachable from the UI.
Launch argument `-BRUCE_DEMO 1` (also in the scheme, disabled) or env `BRUCE_DEMO=1`. No API calls, no remote images, no map tiles; book, cancel and check-in only
change local state. `BRUCE_SCREEN=<name>` opens a screen directly (same names as macOS: `explore`, `classes`,
`detail`, `studio`, `checkin`, `myclasses`, `friends`, `notifications`, `menu`, `account`, `settings`,
`rules`, `booked`, `filter`, `search`, `welcome`, …):

```sh
xcrun simctl install booted build/…/BruceiOS.app
SIMCTL_CHILD_BRUCE_DEMO=1 SIMCTL_CHILD_BRUCE_SCREEN=studio xcrun simctl launch booted net.dauernheim.bruce
```

## Code layout

- `../Shared/BruceCore/` is **shared with Bruce-MacOS**: API client (`API.swift`, `API3.swift`), models,
  Keychain `TokenStore`, `AppModel` (navigation state, loading, book/cancel/waitlist/check-in), demo data,
  booking-rule logic and static copy. macOS compiles it through the symlink
  `Bruce-MacOS/Sources/BruceMacOS/Shared`.
- `BruceiOS/` is the iOS UI layer: native `TabView` and a `NavigationStack` per tab bound to
  `AppModel.stacks`, with sheets driven by `AppModel.sheets` (deeper sheet routes push inside the sheet).
- Copied rather than shared: the colour constants (`Theme.swift`, made adaptive for dark mode),
  `FlowLayout` and the opening-hours logic (`StudioHours`). The views are rewritten for iOS. The QR scanner
  uses `AVCaptureMetadataOutput` instead of macOS's Vision pipeline.

## Liquid Glass

System glass tab bar (minimises on scroll) and glass toolbars, with the heavy wide title pinned in the bar
(`sharedBackgroundVisibility(.hidden)`). Search is a standard `.searchable` field on Explore; results overlay the page only while searching
with a non-empty query, so Cancel returns to the exact page state. Five tabs leave no room for a separate search-role tab without
iOS falling back to "More". Also used:

- `.glassEffect()` cards, chips and capsules, with `GlassEffectContainer` around chip rows, day pickers and target lists;
- `.buttonStyle(.glassProminent)` tinted lime for Book, Log in and Show ticket, and red for Cancel;
- `.buttonStyle(.glass)` for secondary actions;
- glass partial-height sheets (rules, menu, filter, quick check-in);
- `scrollEdgeEffectStyle(.soft)`.

The Check in tab is a full-screen camera with clear-glass overlays and one-tap check-in targets.

## Behaviour and safety

Same as macOS: there is no dry-run mode. **Book, Cancel and Check in send real requests** when logged in.
Book and Cancel go through the booking-rules sheet; check-in always asks for confirmation (QR scan or tap).
Waitlist, bookmarks, favourites, notification and social toggles are wired. Account changes, plans, pause,
checkout, payments, vouchers, signup and password reset are **display-only**. Login uses
`POST /v52/access/authenticate`, stores the session in the Keychain (service `net.dauernheim.bruce`) and
never stores the password. No personal data is hard-coded.

## Areas and search

- **Custom areas** (Filter → Area): like the original app, they are stored on the device only. The
  observed traffic shows no area endpoint (see [API.md](../API.md)).
  - Save without drawing stores the visible map rectangle.
  - "Draw" captures a freehand outline (finger on iOS, mouse drag on macOS), simplified with
    Douglas–Peucker to at most 50 points and shown as a lime overlay.
  - Saved areas become chips. Selecting one filters studios (point in polygon on their coordinates) and
    classes (by their studio). Long-press (iOS) or right-click (macOS) → Delete, with a confirmation.
  - Code: `Shared/BruceCore/Areas.swift` (`AreaStore`, `LocalAreaStore`).
- **Search** is the tab bar's bottom accessory, a glass field.
  - iOS 26.1+: shown only on the Home and Explore roots. On iOS 26.0 an accessory can't be limited per tab,
    so it shows everywhere.
  - Typing switches to Explore and overlays the results. ✕ clears the search and returns to the
    originating page, with its state intact.

## Check-in

- **Check in tab**: the camera QR scanner only (as in the original).
- **Home top-bar control**: one suggested place in a glass card. The suggestion is chosen in this order:
  1. a booking whose check-in window is open now;
  2. the nearest check-in studio within 300 m, when location is allowed;
  3. the last visited studio.

  An "Other studios" list sits under the card: searchable, with Pinned, Today's bookings, Recent (5) and All
  sections, and swipe to pin (pins are local only).
- Every check-in is confirmed first.
- Logic lives in `Shared/BruceCore/CheckInLogic.swift`; macOS uses the same logic without location.

## Real data, images, location

- **Images:** loaded through `ImageStore` (shared). It survives view re-creation (AsyncImage cancelled its
  loads during real-data updates), deduplicates requests and caches in memory and on disk.
- **Location:** when-in-use, asked the first time Home appears after login (like the original), or from
  "Use my location", "Near me" or Settings. It drives distances, Home
  "Nearby gyms" (sent as coordinates) and the check-in suggestion. The city centre is the fallback.
- **Errors:** load errors show a glass retry banner. An expired or rejected (401) token clears the session and
  opens Log in.

## Performance (measured against the public endpoints, logged out, simulator)

| What | Before | After |
|---|---|---|
| Studio list (691, `/v52/studio/filter`, `limit` capped at 30 by the server) | 25.7 s sequential, blank until done | first page 0.87 s, all 6.6 s (cold); cached list 0.09 s + background refresh 7 s (warm) |
| One city day of classes (`/v52/class`, ~1000 classes) | 6–14 s sequential | 2.9–5 s (8 time windows in parallel), first rows after the first page |
| Studio Classes tab | 14 sequential day requests | 3 days first, then 4 more as the list end appears (14 max) |

How:
- **Studios:** a light pass (plain fields, no includes, about 0.15 s per page) streams names and photos
  first. Then full pages load in parallel over balanced id ranges; the cursor is just base64 `id::<n>`.
- **Studio cache:** the list is cached on disk and shown instantly on the next launch, then revalidated.
  The `cache_expire_seconds` hint is honoured; it is null for this endpoint, so it always revalidates.
- **Classes:** list requests drop the credit-cost and dynamic-price includes.
- **No duplicate loads:** in-flight loads are shared (studios, each day, each studio's classes), and
  distances are precomputed once per studio list or location change.

`[timing]` lines are printed in Debug builds.

Rendering:
- **Observation:** `AppModel` uses `@Observable`, so each view re-renders only for the properties it reads.
  While 691 studios stream in, body evaluations went from RootView 54 → 4, ExploreView 55 → 23 and
  StudioCard 226 → 39, measured with `Self._printChanges()` over the same scenario.
- **Streaming:** updates are coalesced to about 3 per second.
- **Studio cards:** value-only and `Equatable`, so unchanged cards are skipped.
- **Studio lookups:** O(1) through an index; they used to scan the whole list for every row.
- **Dates:** formatters are cached and parsed timestamps memoised.
- **Off the main actor:** images are decoded with ImageIO, downsampled to the requested Cloudinary size, and
  the memory cache is capped by bytes. The studio cache is encoded and decoded off the main actor too.
- **Location:** only publishes moves of more than 50 m.
- **Glass:** used on bars, buttons and containers; list cards use a thin material.

## Info.plist / privacy

- `NSCameraUsageDescription`: QR check-in.
- `NSLocationWhenInUseUsageDescription`: check-in suggestion and nearby studios.
- `ITSAppUsesNonExemptEncryption = NO` (HTTPS only).

## TestFlight

`scripts/testflight.sh` archives (Release, `generic/platform=iOS`), exports with
`Config/ExportOptions.plist` (`app-store-connect`, automatic signing, internal testing only) and uploads
through `xcodebuild -exportArchive` (destination `upload`). It uses `-allowProvisioningUpdates` with the
App Store Connect API key so signing assets are created automatically. The build number is a UTC
timestamp.

Personal values are never committed. Copy `.env.example` to `.env` (git-ignored) and fill it in, or export
the variables; values already in the environment win over `.env`:

```sh
cp .env.example .env        # then edit TEAM_ID, ASC_KEY_ID, ASC_ISSUER_ID
scripts/testflight.sh
```

| Variable | Default |
|---|---|
| `TEAM_ID` | required; falls back to `DEVELOPMENT_TEAM` in `Config/Local.xcconfig` |
| `ASC_KEY_ID` | required |
| `ASC_ISSUER_ID` | required |
| `BUNDLE_ID` | `net.dauernheim.bruce` (use your own App Store Connect app) |
| `ASC_KEY_PATH` | `~/.appstoreconnect/private_keys/AuthKey_<ASC_KEY_ID>.p8` |
| `BUILD_NUMBER` | UTC timestamp |
| `MARKETING_VERSION` | from the xcconfig |

`scripts/testflight.sh --no-upload` exports an `.ipa` locally instead of uploading.
